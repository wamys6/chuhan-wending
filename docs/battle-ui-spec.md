# 对战界面规格（Godot 版）

> 2026-11-02 版式重排后定稿。所有数值同时写在 `godot/scenes/battle.gd` 顶部常量区，
> 改版式改常量即可，不要在函数里散写数字。

## 一、栅格

设计分辨率 **1440×900**，`project.godot` 用 `canvas_items` + `expand`，因此所有坐标是逻辑像素，
实际窗口按比例缩放，版式不重排（只做等比）。

| 项 | 值 | 依据 |
|---|---|---|
| 左/右边距 | 24 | 四边等宽，左右对称；之前是左 20 / 右 44 |
| 上边距 | 16 | 顶部敌将卡贴边，留出视觉呼吸 |
| 下边距 | 20 | 主将卡与按钮共用同一底线 880 |
| 左栏 | x 24~232，宽 208 | 放战报；右缘与军阵第一列（244）留 12 间隙 |
| 右栏 | x 1044~1416，宽 372 | 放主将技能 + 结束回合（各 176×52，间隙 20） |
| 军阵 | 三列 296×156，间隙 32，x 244~1196 | 满编 3 张 = 3×90 + 2×4 = 278，左右各余 9 |

垂直节奏（自上而下）：

```
16   敌将卡（460×88）
116  敌方军阵列框（156 高）   → 底 272
294  楚河汉界中线（中间留 420 空档给回合提示）
316  我方军阵列框（156 高）   → 底 472
570  手牌（128×186）          → 底 756
792  我方主将卡 / 828 操作按钮 → 底 880
```

战报面板最小高度 **356**，底边 472 与我方军阵底边齐平（共用一条水平基线）；
内容变多时向下生长，上限 660（止于主将卡上方 16px）。

## 二、字号阶梯（下限 13px）

| 档 | 字号 | 用途 |
|---|---|---|
| 微 | 13 | 列名、敌将卡「点此直取敌将」、牌库/疲劳行 |
| 辅助 | 14 | 战报正文、关卡目标、军粮数字、提示条 |
| 正文 | 16 | 主将卡名字/血量、卡牌费用与攻血角标 |
| 标题 | 20 | 回合提示、按钮文字 |
| 显示 | 26 | 弹层标题（结算、暂停、掉线） |

**下限 13px，硬约束。** 设计分辨率 1440×900，1366×768 笔记本上整屏缩到 **0.853**，
12px 只剩 10.2px —— 汉字「牌库」「疲劳」的撇捺糊在一起（2026-11-07 按 1:1 裁切实测）。
13×0.8=10.4px 是可辨底线，再小就不许出现。`legibility_test.gd` 会扫全部 `.gd` 强制，
连 `add_theme_font_size_override` 与 `const FS_*` 一起扫。

中间档（15/17/18/19/22/23/24/28/30）在弹层、图鉴、结算里仍有遗留，属历史包袱；
**新写的界面只用上表五档**，别再引入新档位。

## 三、组件规格

### 敌将 / 主将卡（460×88）

| 元素 | 位置 | 规格 |
|---|---|---|
| 头像 | (6,6) | 76×76，`STRETCH_KEEP_ASPECT_COVERED`，不接收点击（点击落到卡片上） |
| 名字 | (94,6) 210×26 | 20px 墨色；放不下自动降到 16（`UiTheme.fit_size`），仍超才省略号 |
| 血量 | (94,42) 180×30 | 20px 朱砂；≤30% 转 `#c0261c` |
| 军粮点阵 | (312,24) | 10 颗，点径 10，间距 4；实心 `#33555e`／空心（描边）／灰（未解锁） |
| 军粮数字 | (312,40) 136×20 | 14px `#33555e` |
| 牌库/疲劳 | (312,64) 136×16 | 13px 辅助色；余量 ≤3 转 `#8a6416`，抽空转朱砂「疲劳 N 伤」 |
| 敌将提示 | (312,5) 136×15 | 13px，右对齐 + 裁剪，仅敌方卡片有 |
| 险印 | (280,44) 28×28 | 朱砂圆；只在「可达敌军总攻 ≥ 主将血量」时亮 |

右栏三行（点阵 24 / 军粮 40 / 牌库 64）都从 x 312 起、宽 136，与左侧头像+名字+血量分栏。牌库行 y=64 是因为 Label 实际行高被字号钳到 23px：再往下 1px 就压到血条框内缘（框高 88）。

**这两处宽度是中英共用的，量的时候要按最长的那种语言量**（`legibility_test.gd` 已钉）：
名字 210px —— 中文「项羽 · 西楚霸王」137px，英文「Xiang Yu · Hegemon-King」20px 要 252px、
16px 204px，所以按宽度降一档（`FS_TITLE → FS_BODY`）；再长的语言就得改版式而不是继续缩字号。
提示 136px —— 中文「点此直取敌将」78px，英文旧译「Click to strike the commander」192px 会往左
溢出卡片、压到顶部关卡目标条，现收短为「Click to attack」90px，并且开着 `clip_text`。

军粮色用**黛青 #33555e**：水墨体系里的冷色，保留「资源」的语义区分，且不像原来的纯蓝 #3d5a80 那样跳。

### 关卡目标条（(484,22) 856×48，最多两行）

左界让开敌将卡（484）、右界让开暂停（1340）。**允许两行，不缩字号**：中文 8 关最长 619px
永远一行；英文 5 关超 856px（最坏的垓下 **1281px**），两行预算 1712px 刚好够。
这句是战斗里最重要的一句文案，16px 两行比 13px 一行好读。下方到军阵框（y 116）还有 44px 余量。
`legibility_test` 会按 8 关 × 2 语言量一遍，并断言「至少有一关真的需要换行」——否则这条判据
就没在验证任何东西。

### 军阵列框（296×156）

- 结构：顶部 **24px 列名带** + 部队区 124 + 上下各 4 的呼吸缝（`RANK_PAD_Y`）。
- 部队 **90×124**，列内间隔 4。满编 3 张总宽 **278**，框宽 296 里左右各余 **9**。
  （原来 96×132，满编正好 296 = 框宽，牌边与框线严丝合缝地重合，满场看不出列界。）
- 攻血章横向不出血（x 0 与 86）：满编时相邻两牌的章之间还剩 4px，不会互撞。
- 部队从「框顶 + 24 + 4」起摆，因此 3 个单位满编也压不到列名。

**超编兜底（一列 >3 张）**：列上限由 `COLUMN_LIMIT` 决定，规则层会拒绝第 4 张；
万一上限被调大或异常状态灌进来，`_rank_scale(n)` 把整列等比缩小塞进列框（可用宽 288 = 296 − 4×2）：

| 张数 | 缩放 | 单张可见宽 |
|---|---|---|
| 3（常规满编） | 1.00 | 90.0 |
| 4 | 0.77 | 69.7 |
| 5 | 0.62 | 55.6 |
| 6 | 0.51 | 46.3 |

缩放轴在牌中心（`pop_in` 要用），所以摆位时左上角按 `SIZE/2·(1−s)` 反向补偿；
垂直方向同步重新居中（`_rank_top_y`）。**任何张数都不溢出到邻列**。
- 列名 12px，`INK_SOFT @ 0.8`，居中于列名带。
- 边框 `INK @ 0.2`，底色 `白 @ 0.3`；悬停手牌预览落点时换金色描边 2px。

### 战报（208 宽，高 356~660 自适应）

- 标题「战 报」14px，位于 (12,8)；正文可视区从 y 36 起，宽 **184**。
- 正文 14px，行距 3，条目间 separation 4。**中文每条最多 2 行，英文 3 行**：
  英文句子比中文长六成，内宽 184 下最长一条实测 539px ≈ 2.9 行，钉 2 行会静默截断半句。
- **回合抬头必须单行**（`—— 第 9 回合 · 我方`，不带「·」前缀、用墨色不用辅助色）：
  184px 一行只放得下 13 个汉字，旧文案「—— 第 9 回合：我方（军粮 10/10）」实测 231px，
  在每块屏幕上都会折两行、而且断在「军粮」两个字中间。军粮在双方主将卡上一直可见，
  战报要的是顺序不是记账。宽度由 `legibility_test.gd` 用字体真实度量卡死。
- **最新一条排最上面**：战报回答的是「刚刚发生了什么」。旧的往下滚，超出从末尾（最旧）丢。
- 条数上限 10，且受可视区高度二次裁剪。
- 面板高度 = 内容高 + 48，clamp 到 [356, 660]。

### 手牌（128×186，扇形）

- 区间 `x ∈ [24, 1416]`，但两端各让出 **26px 旋转余量**（`HAND_ROT_HALF`），实际排布区 `[50, 1390]`。
- **与主将卡靠垂直分层错开，不靠横向避让**：主将卡 y 792~880，手牌底 770。当年为此把区间右移到 496 是误判，导致牌少时整排偏右。
- 排布：`start_x = clamp(720 - 总宽/2, 50, 1390 - 总宽)` —— 牌少时居中于屏幕，牌多时铺满。
- 间距 `min(136, (1340 - 128) / (n-1))`，7 张时仍 136（不重叠），10 张压到 134.7（不重叠）。

**扇形参数**（`battle.gd` 顶部常量）：

| 参数 | 值 | 依据 |
|---|---|---|
| 旋转轴 | 底边中点 `pivot_offset = (64, 186)` | 牌"握在手里"，下端固定、上端散开 |
| 最大旋转角 | ±8°（`HAND_MAX_ROT`） | 10 张时相邻牌顶角仍留约 8px 间隙 |
| 弧落 | 两端 +14（`HAND_ARC`） | 中心牌 y=570、两端 584，牌底 770 仍在主将卡 792 之上 |
| 角度分布 | `θ = 8° × d`，`d = (i - (n-1)/2) / ((n-1)/2)` | 线性，中心 0° |
| 弧落分布 | `dy = 14 × d²` | 平方，中间平、两端陡，接近真实握牌弧线 |

**悬停**（`HAND_HOVER_*`）：

| 项 | 值 | 说明 |
|---|---|---|
| 放大 | 1.3 倍（166×242） | 牌顶 = 570 − 14 − 186×0.3 = **500.2**，给说明行留 5px |
| 上浮 | 14px | 与放大叠加 |
| 旋转 | 归零 | 放大后可正着读 |
| 层级 | `z_index = 100` | 最高 |
| 邻牌让位 | 紧邻两张各推开 `min(余量/2, 40)` | 牌多无余量时为 0，只靠放大牌自己盖 |

> **放大倍率与说明行位置是绑定的**：1.4 倍会把牌顶推到 481.6，说明行就没地方站（实测会被整条盖住）。改倍率必须回头看 `hand_hint.position.y`。

**悬停时不弹 `CardTip` 浮层**，规则文字改挂手牌上方一行：

- `hand_hint`，位置 (24, 474)，尺寸 1392×21，14px，`INK_SOFT`，居中，`z_index = 200`（必须高于悬停牌）。
- 位于军阵框底 472 之下、悬停牌顶 500.2 之上，不遮任何东西。
- 内容：`卡名　描述`。

**可出牌标识**：外扩 4px 的金线（`HAND_GOLD alpha 0.92`，2px，圆角 9），金色＝全局"可操作"语义色（同可攻击单位、落点列）。不可出＝`modulate (0.62, 0.60, 0.58, 0.9)`。

**牌底厚度**：`_frame` 的 `border_width_bottom = 4`（其余 2px），模拟宣纸裁切厚度。

(496, 838) 528×28，14px 居中。与操作栏同一水平带、横向错开，不压按钮也不压主将卡。

## 四、层级

| 层 | 内容 | 说明 |
|---|---|---|
| 0 | 背景纸色 + 中线 | 不可交互 |
| 1 | `board_layer` 军阵列框 + 部队 | 部队 `MOUSE_FILTER_STOP`，其余 IGNORE |
| 2 | `hand_layer` 手牌 | 手牌可点 |
| 3 | `fx_layer` 动画/飘字 | 全部 IGNORE |
| 4 | `ui_layer` 面板/按钮/战报 | — |
| 200 | `hand_hint` 悬停说明行 | 必须高于悬停牌的 100 |
| 100 | 悬停中的手牌 | 放大时压过其他牌 |
| 70 | `CardTip` | 保留组件，对战界面已不再弹出（图鉴仍可用） |
| 50 | 受击红闪 | `ColorRect`，IGNORE |

## 五、已验证

`tests/battle_ui_test.gd` 49 项，覆盖：点牌能出、双方部队同存、手牌明暗随回合走、
战报不溢出且最新在顶、列名不被部队压、部队不越列框、字号五档、左右边距 24、
手牌底在主将卡之上（垂直分层）、旋转余量覆盖两端外伸量、
扇形两端倾角 ±8 且对称、弧落 14、悬停放大 1.3 且旋转归零且置顶、
悬停牌顶让开说明行、悬停牌底不压主将卡、说明行显示与清空。

改版式后必跑：`battle_ui_test` + 最小回归集（replay/campaign/pvp）+ `--tour` 截图对照。
