# 《楚汉·问鼎》开发路线图

> 2026-11-01 制定。出发点：现有版本（25 张卡 / 2 英雄 / 完整战斗引擎）离"完整游戏"还有多远，以及如何走到 Steam 上架。

---

## 一、现状诊断

### 已经有的（价值最高，不要推翻）

- **完整战斗循环**：军粮曲线、每回合抽牌、三列军阵站位、守御/迂回/远程、疲劳制、先机补偿、双英雄技能
- **可用的 AI**：三档难度，名将档会算斩杀
- **工程基础**：2484 行纯前端代码，零依赖零构建
- **平衡数据**：480 局模拟验证，刘邦 49.6% / 项羽 50.4%
- **表现层**：程序化音效（10 种）、入场/受击/突进动画、悬停放大预览、战报文字条
- **配套**：新手教学、自由构筑、mulligan 换牌

### 缺的三层

| 层级 | 内容 | 状态 |
|---|---|---|
| 第一层 · 战斗循环 | 一局怎么打 | ✅ 已成型 |
| 第二层 · 构筑循环 | 怎么换套路 | 🟡 有界面，但 25 张卡组合空间太小 |
| 第三层 · 成长循环 | 为什么明天还想打开 | ❌ 完全缺失 |

**核心结论：现在的短板不是功能，是"继续玩的理由"。**

---

## 二、关键战略决策：改为 PvE roguelike 战役

### 为什么不做"炉石式 PvP 打 AI"

1. **正面撞炉石**：玩家会问"为什么不去玩免费的炉石"。炉石有数百张卡、真人对手、十年内容积累。
2. **AI 不是对手**：真人对战的乐趣来自揣测意图；AI 只是一个可解谜题，破解完就腻。
3. **PvP 需要的能力单人没有**：服务器、匹配、反作弊、每周平衡补丁、持续运营。

### 改为"楚汉 roguelike 战役"

Steam 上活下来的单人卡牌游戏几乎全是 PvE roguelike（杀戮尖塔、怪物火车、小丑牌、Inscryption）。这个品类对单人开发者友好，原因：

- 不需要服务器和匹配
- 不需要平衡两个对称牌池（PvE 里"这卡超强"是优点）
- 内容可以无限扩展（每关加几张卡就是新内容）
- 失败重开天然产生成长循环

### 形态对照

| | 当前 | 改为 |
|---|---|---|
| 玩家做什么 | 选英雄 → 打一局 → 回主菜单 | 沿楚汉历史路线推进，一关接一关 |
| 每关 | 标准对局 | 带特殊规则的战斗 |
| 赢了之后 | 无 | 从 3 张牌里选 1 张加入牌组 |
| 输了之后 | 回主菜单 | 重来，但解锁了新的起始卡/英雄 |
| 引擎改动 | — | **一行都不用改** |

## 三、四阶段路线

### 阶段 1 · 补内容与表现力（约 2-3 周）

- [x] 卡池 25 → 45 张（兵种各档位变体、更多人物牌、更多计谋）✅ 2026-11-01
- [x] 新增 3 个关键词机制：冲锋、死战、连击 ✅ 2026-11-01
- [ ] 补齐全部卡面立绘（当前 4/46）
- [x] 背景音乐（Web Audio 程序化生成：古琴拨弦 + 箫 + 低音持续，地图/对局双场景）✅ 2026-11-01
- [x] 卡牌图鉴页（45 张按阵营/类型筛选、标注是否在战役牌组）✅ 2026-11-01

**目标**：一局打完还想再来一局。

### 阶段 2 · 楚汉战役模式（约 3-4 周）★ 分水岭

8 关历史路线，每关特殊规则。✅ 全部 8 关已上线（2026-11-01）：

| 关卡 | 规则 | 设计意图 |
|---|---|---|
| 1 沛县起兵 | 敌将 14 血，教学强度 | 熟悉系统 |
| 2 鸿门宴 | 存活 10 回合，手牌上限 3，玩家 12 血 | 限制条件下的防守 |
| 3 彭城之战 | 敌方 1 预置轻骑，玩家首回合 +2 军粮 | 劣势局翻盘 |
| 4 荥阳对峙 | 敌将 22 血 + 据城死守牌组 | 攻坚（破守御） |
| 5 井陉背水 | 玩家 16 血、敌军 1 队列阵 | 速攻 |
| 6 潍水之战 | 敌将 24 血（龙且专属牌组），玩家 +3 军粮 | 大场面清场 |
| 7 固陵之战 | 玩家 18 血、手牌上限 4、敌方首回合 +2 军粮 | 孤军防守反击 |
| 8 垓下决战 | 敌将 30 血 + 预置骠骑 + 敌 +2 军粮 | 最终决战 |

配套系统（全部就绪）：

- [x] 战后三选一加牌（构筑循环的来源）
- [x] 关卡进度存档（localStorage + 内存兜底）
- [x] 战前剧情文字过场
- [x] 战役失败后重试机制
- [x] 每关专属敌军牌组（`rules.enemyDeck`）与敌方首回合军粮（`rules.enemyStartMana`）

**目标**：验证"打完这关想不想打下一关"。想 → 方向成立，扩到 8 关只是体力活。

### 阶段 2.5 · 战役随机化（roguelike 三支柱）✅ 2026-11-01

- [x] 军师系统：开局 5 选 3 择 1，被动贯穿整局（张良/萧何/韩信/樊哙/陈平）
- [x] 行军事件：关与关之间随机触发，10 个事件三选一（生命/军粮/得牌/删牌）
- [x] 奖励池随机化：全局卡池按稀有度分档抽取，同名 ≤2 张
- [x] 存档 v2（v1 自动迁移）+ 一次性加成"用后清零"
- [x] 平衡校准：军师通关率 11-20%（`test/tune-roguelike.js`）

### 阶段 2.6 · 上手体验（onboarding）✅ 2026-11-01

- [x] 首战六步引导：对手目标 → 军粮 → 出牌 → 攻击规则 → 主将技能 → 结束回合；聚光灯式提示，可跳过、只做一次、随时可从主菜单「重看新手引导」重置
- [x] 关键词悬停释义：守御 / 迂回 / 远程 / 冲锋 / 死战 / 连击在牌面描述中带虚线下划线，悬停出气泡解释
- [x] 规则首次触发提示：单位不能攻击、军粮不足、前锋挡路、列已满——每种只说第一次，避免"点了没反应"的困惑

### 阶段 2.7 · 表现力（BGM 与战斗反馈）✅ 2026-11-01

- [x] 程序化背景音乐：五声音阶小步游走生成旋律（古琴拨弦音色）+ 箫长音 + 低音持续垫底，地图舒缓 / 对局加快并加鼓点；切换淡入淡出，静音开关统一管理，遵循浏览器自动播放策略（首次点击后起声）
- [x] 战后结算面板：剩余血量 / 造成伤害（溢出不计）/ 出兵 / 用计 / 回血，回合数与牌库余量，高伤直取主将时给徽章
- [x] 主将受击时战场震动反馈
- [x] 修复：悬停预览卡在界面重建后不消失的问题（会悬空挡住结算标题）

### 阶段 2.8 · 长线系统（图鉴 / 成就 / 战绩）✅ 2026-11-01

- [x] 卡牌图鉴：45 张全量展示，阵营（中立/汉/楚）×类型（兵种/计谋）组合筛选，右上角阵营徽章，牌组里的牌标「牌组 ×N」
- [x] 成就系统：19 项，分「战阵（单场表现）/ 战役（推进进度）/ 阅历（长期积累）」三组；结算页直接弹出本次解锁条，非战斗场景（选军师、遇事件、通关）用提示条报
- [x] 战绩页：总场次/胜率/最长连胜/战役进度/累计伤害六格 + 战役明细（最远关卡、最大牌组、军师与事件阅历）+ 战阵明细（最速取胜、最凶险胜仗、各难度胜场）
- [x] 成就只增不减：重开战役、清空战役进度都不影响成就与战绩存档（独立 key chuhan_career_v1）

### 阶段 3 · 打磨成"像商品"（约 2-3 周）

- [x] 主菜单重做（有氛围、有动画）✅ 2026-11-01：左右刘邦/项羽立绘剪影 + 中央雾气呼吸 + 楚河汉界竖线，标题墨迹晕开入场、元素顺序浮现；主菜单配更慢的 title 曲

### 阶段 3.5 · Electron 桌面化 ✅ 2026-11-01

- [x] Electron 壳：1440×900 可调窗口（最小 1100×700）、无边框菜单、外链走系统浏览器；`npm start` 开发（F12 开 DevTools）、`npm run dist` 打 win-x64 免安装目录（dist/楚汉问鼎-win32-x64/，约 500MB，Steam 直接上传该目录）
- [x] 桌面桥（electron-preload.js）：contextIsolation 隔离，只暴露 `window.Desktop.{isDesktop, toggleFullscreen, fullscreenState}`；设置面板全屏按钮在桌面端走原生全屏、浏览器端仍走 Fullscreen API，一套代码两端兼容
- [x] 后台不节流：`CalculateNativeWinOcclusion` 禁用 + `backgroundThrottling: false`，窗口被遮挡/最小化时 BGM 定时器不掉帧
- [x] 验收：`test/desktop-check.js <port>` 对开发版与打包版各跑一遍（桌面桥注入、原生全屏进出、进对局、无 JS 报错）全部通过
- [ ] 应用图标 .ico（打包时 `--icon`，等 Steam 素材一起做）

## 四、Steam 上架门槛（2026 年数据）

| 项目 | 要求 |
|---|---|
| 上架费 | 每款 $100，收入满 $1,000 后退还 |
| 抽成 | 30%（开发者拿 70%） |
| 游戏形态 | 必须是原生可执行程序，不接受网页游戏（Electron 打包可解决） |
| 流程时间 | 付款后 21 天冷静期 + Coming Soon 页公开 2 周 + 审核 1-5 个工作日 = 最少 4-6 周 |
| 税务 | 中国开发者填 W-8BEN，需银行账户 |
| 商店素材 | 至少 5 张真实截图（建议 1920×1080）、预告片、6 种尺寸胶囊图（每张必须含游戏名文字） |
| AI 内容 | 必须如实申报哪些内容由 AI 生成、用在哪里 |

### 两个不影响上架但决定成败的事实

1. **上架 ≠ 有人玩**。Steam 每年上架一万多款游戏，绝大多数没有曝光。决定曝光的是：品类标签是否清晰、胶囊图在 150×69 缩略图下是否可辨、有没有主播愿意播。
2. **首发印象只有一次**。带半成品上架，差评会定型且很难挽回。发布应该是项目终点，不是中途站点。

## 五、范围纪律（明确不做）

以下功能即使是成熟卡牌游戏标配，v1 也不做：

- 在线真人 PvP（需要服务器与运营，个人开发者无法承担）
- 段位/天梯系统
- 内购、卡包抽卡
- 多语言配音
- macOS / Linux 版本（Windows 先跑通，占玩家绝大多数）
- 移动端移植

---

## 六、当前唯一建议的下一步

阶段 1（卡池+关键词）、阶段 2（8 关战役）、阶段 2.5（战役随机化）已完成。随机化后的验证结论：军师把通关率从 2% 提到 11-20%，且每个军师对应不同打法；事件与随机奖励让每局构筑路线都不同。

剩余优先级建议：

1. **续关存档 + 卡牌图鉴页**——关掉浏览器战役就断（当前只存进度不存"打到第几关的局中断点"），图鉴是 45 张卡池的展示出口。
2. **背景音乐**（水墨风格古琴/箫，Web Audio 合成，无需素材）。
3. **补卡面立绘**（当前 4/46，用户自行解决）。
4. **阶段 3 · 打磨成"像商品"**（主菜单、设置、存档位、成就、双语）。
5. **阶段 4 · Electron 打包 + Steamworks**。
