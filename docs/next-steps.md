## ① 内容扩展（下一个大块，用户已定）

### 1.0 奖励页「不取牌 · 改删一张」✅ 2026-11-02
- **为什么**：奖励原来只有三选一，玩家没有拒绝权；8 关下来四成牌组是被迫拿的。
- **定价过程**：先测「跳过 + 补血」——无效（血量是纯噪声，见 design doc 新增一节）；再测「跳过 = 删一张」——第 4 关 +7pp、第 8 关 +26pp，强于一张奖励牌。
- **实现**：`Campaign.MIN_DECK = 15` / `can_remove_card()` / `remove_card()`；`App.take_reward_skip()`；`reward.gd` 次要按钮 + 覆盖式选牌层（10 列，28 张三行）。
- **测试**：campaign_test 52→62 项；i18n_test 增扫覆盖层；全量 1030 项 + E2E 15 全绿。

### 1.0b 难度曲线 + 军师收敛 + 心魔/天时 ✅ 2026-11-02
- **第 3 关断崖**：彭城原来是「预置轻骑 3 费 3/2」，通关率 32~36%；换成「预置戍卒 1 费 1/2」后 52~55%。第 7 关撤掉预置，收尾变成 58 → 46 → 35 的两级台阶。八关曲线现在是 **70/78/55/56/45/58/46/35**（500 局口径）。
- **军师从门槛变风格**：樊哙 +2/+1 → **+1/+1**、陈平起手 +1 → **+2 张**；收益带从 9~30%（3.3 倍）压到 **13~20%（1.5 倍）**。军师的数值全部收进 `js/engine.js` 的 `ADV` 对象与 `rules_engine.gd` 的同名常量，改数值只需改一处。
- **心魔 3 级**（通关解锁、累计生效）：主将 -3 → 起手少摸一张 → 敌军首回合 +1 粮。实测 19/16/10/6。**只做 3 级是数据结论**：可用的负向杠杆每一个都值 -6~-13pp，8 关连乘后第 4 级就掉到 1%。
- **天时 6 种**（每局随机一个、八关全程生效，三利三弊）：清风/丰年/霜降/苦寒/离火/星变。实测 10~27%，是"每局手感不同"的来源，不是"抽到坏天时就输"。
- **顺带修的真 bug**：`openingDraw` 为负时引擎啥也不做（`for i < -1` 直接跳过），"起手少摸一张"以前是空效果。
- **测试**：replay 333→413（新增心魔/陈平群伤/彭城场景）、campaign 62→120、codex 140→148；
  当时全量 1176 项 + E2E 15 项全绿（后续表现层又加到 1186 + E2E 19）。

### 1.0c 心魔 / 天时的表现层 ✅ 2026-11-02
- **为什么**：1.0b 把心魔和天时做成了纯文字 chip，玩家要到第 3 关才发现「怎么我起手少一张」。机制已经存在，缺的是"这一局不一样"的第一印象。
- **做了什么**：
  - **天时揭晓页**（新场景 `scenes/omen.tscn`）：拜师之后、进地图之前，摇签（`lottery`）→ 签纸落下 → 落地一震 + 铜锣（`omen`）→ 「受命出征」。签纸上有吉/凶朱砂印、天时尾字水印（`OMEN_GLYPH` 按 id 查，与语言无关）。
  - **心魔选择的即时反馈**：点某一级 → 盖章音效（`seal`）+ 落印回弹动画；页面四周按等级加深暗红暗角（0.16/级，`Widgets.vignette`）。
  - **成就横幅让位**：首次选军师的成就原来会和揭晓页抢画面，改成 `App.flush_announce()` 在仪式结束时补播。
- **测试**：新增 3 枚音效（audio 83→89）、揭晓页进 i18n 扫描（i18n 180→184，含「真的建出来了」断言）、E2E 15→19（择师→揭晓→地图）。

### 1.0d 素材瘦身：包体 317MB → 134MB ✅ 2026-11-03
- **为什么**：卡池要扩到 70 张就得再加 24 张立绘（+75MB）。扩之前先算账，发现 317MB 里 200MB 是**无损打包的立绘**、42MB 是**两个字重的完整中文字库**——不是内容多，是没压。
- **纹理**：74 个 `.import` 的 `compress/mode` 从 0（无损）改 1（WebP 有损），`lossy_quality=0.8`。卡图 200MB → 27MB。整屏 PSNR 39.8~43.8dB，肉眼可察差异像素 0.03%~1.4%；q0.30 的极端对照只降到 36.6dB，说明这个量级的图对 WebP 极不敏感。
- **字体**：`tools/subset-fonts.py` 扫全部 `.gd` 字符串 + `data/*.json`，取实际用字（950 个）做子集，47.7MB → 1.8MB。源字体移到 `assets/fonts-src/`（**工程目录之外**，否则会被 `all_resources` 打进包）。
- **守卫**：新增 `fonts_test.gd`（2 项），扫源码字符比对 `get_supported_chars()`，加新文案漏字直接报红并提示重跑子集。
- **结论**：同一批素材、零可见画质损失，省下 183MB。**扩池的 24 张图现在只值 +6MB，不再是包体顾虑**——真正要担心的只剩风格统一。
- **测试**：全量 **1188 项 + E2E 19** 全绿（新增 fonts_test 2 项）；exe 134MB，包内 E2E 19/19。

### 1.2 死战专精（让 Build 靠卡堆也成立）✅ 2026-11-03
- **为什么**：1.1 的结论是「死战路线的差异化只能靠军师，靠不了卡堆」。1.2 先量了成因：
  不是选不到（三选一里有死战牌的概率 76%，专精玩家实际拿到 7.6 张、浓度 27%），
  而是**选了没用**——每多一张只值 1~2 点属性。这同时否掉了"精英关发两张"和"定向奖励"。
- **做了什么**：牌组里死战牌**占比**达到 20%/25%/30% → 死战召唤的援军 +0/+1、+1/+1、+2/+2。
  只对死战触发的召唤生效（战吼召唤不吃），只对玩家生效。档位由 `Campaign.engineRules` 注入
  `rules.lastStandAtk/Hp`，引擎只认这两个数字。
- **为什么用占比不用张数**：牌组从 20 张长到 28 张，张数门槛会随规模漂移；占比门槛
  让专精流第 3~4 关就开始吃到，而按质量选牌的普通玩家全程不到 20%。
- **实测**：死战优先 7% → **13%**（+6pp），与"按质量选牌"的 14% 打平；随机 7% → 9%。
  即死战从"明显更差的路线"变成"能玩的一条路"。完整推导与三次被否的参数见
  [build-lines.md](build-lines.md) 第十二节。
- **遗留**：军师叠加后 28~29%，高于 1.1 定的 23% 上限。但"韩信 + 按质量选牌"也是 28%，
  说明是 1.1 遗留的韩信偏强（`ADV_HANXIN_COUNT` 2→1 待砍），不是本次增量。
- **测试**：replay 541→564（新增 laststand-tier 场景）、campaign 120→133、i18n 185→187；
  全量 **1469 项 + E2E 19** 全绿。

### 1.2b 表现打磨（第二轮：把「看得见但不对」的地方扫一遍）✅ 2026-11-03
- **做法**：不是凭手感调参数，而是把 `--tour` 的 19 张截图逐张放大看，专找「看着不对、但不报错不崩溃」的地方。一次下来抓了四个。
- **修了什么**：
  1. **事件页十个圆形插图全是空白宣纸**（最严重，玩家一直看着它）。成因是 Godot `TextureRect` 的最小尺寸默认等于纹理尺寸（立绘 1024²）：先赋 `texture` 再 `set_size(144)`，144 会被顶回 1024，画面只剩原画左上角一块。改成 `UiTheme.texture_rect()` 统一收口（先 `expand_mode` 再给 texture/size）。同一坑还命中了**主菜单侧立绘**（1024 硬顶）与**对战冲刺残影/阵亡碎片**（巨型贴图）。
  2. **主菜单两侧立绘去掉「贴上去的矩形」感**：立绘上下出血到画外，内缘压一条 200px 同纸色渐隐带（`Widgets.edge_fade`，64×1 渐变贴图，按颜色缓存）。修好 1024→520×900 之后硬边反而更显眼，所以是顺手补的。
  3. **结局页纸面切掉最后一行**：「生涯作战 N 场」被 250 高的面板下边框切了半截。面板放到 288，本局数据与生涯数据之间加一条 0.18 透明度的分隔线，按钮跟着下移到 626。
  4. **敌方主将条的「点此直取敌将」贴边框**：字顶压在边框线上、字底顶着军粮圆点。右栏整体左移到 x=312（右缘 448，留 12px 内边距）、名字栏 222→210 让位、提示行 y=2→5、点阵 20→24。
- **测试**：新增 `art_rect_test.gd` 15 项——钉住成品界面里那几个 `TextureRect` 到底多大（事件 144、菜单 520×900、切片 30×41）、结局页最后一行不被切。全量 1469 → **1496 项**全绿。
- **5. 16:9 / 21:9 宽屏版式**（同批修完）：版式按 1440×900 写死，而 `window/stretch/aspect=expand` 在宽屏上会把画布撑宽（16:9 → 1638，21:9 → 2150），于是每屏整体偏左、右侧多出一条空纸。做法是**舞台整体右移 (视口宽−1440)/2、"多出来的那条"左右均分**：
  - `Widgets.stage_offset()` 算偏移；`App` 在 root 的 `child_entered_tree` 上把 `scenes/` 界面的根节点右移，三条切换路径（`go()`、联机大厅直接 `change_scene`、启动主场景）一次覆盖，窗口尺寸变化时 `size_changed` 重铺一次。
  - 所有「铺满屏幕」的元素改走 `Widgets.fill_screen()` / `bleed_x()`（纸底、立绘底、暗角、弹窗遮罩、聚光灯、设置面板、奖励页横幅），并打 `bleed` 标记供重铺；用 anchor 铺的会跟着舞台一起挪，宽屏下左边留一条没盖到的亮带。
  - 游戏内 1440×900 窗口时偏移为 0，行为与以前完全一致；headless 测试同理，所以旧断言全部不用改。
- **6. 主菜单页脚写到死**：「战役：8 关 · 卡池 46 张 · v0.9」自 1.1 扩池后一直没改。改成从数据算（`GameData.stages.size()` / `GameData.cards.size()`），版本号跟文档对齐到 v0.9.1。

### 1.2c 卡面关键词印（让机制在手里看得见）✅ 2026-11-03

- **起因**：24 张立绘接入后肉眼验收时发现，按文档统一画的「朱砂臂带」缩到 128 宽的卡面上只剩几个像素——**死战牌在手里认不出来**。而 1.2 的死战专精是按「牌组里死战牌占比」判档的，玩家数不出张数，机制等于隐形。
- **做法**：卡面右上角盖一枚小印，与左上费用圆对称。六个关键词各自一枚：死（死战）/ 守（守御）/ 冲（冲锋）/ 迂（迂回）/ 远（远程）/ 连（连击），最多两枚（卡池实测：单关键词 36 张、双关键词 9 张），一行排开右对齐。
- **三档印面**（靠色相分，不靠字认）：朱砂 = 死战（全场唯一一档强提示）、墨 = 守御、靛 = 其余四个战术动作。三色正好是中国印谱里实际有的三种印泥色。
- **两版被否的方案**（都记在 `keyword_stamp.gd` 文件头）：
  1. **空心印**（纸底墨框）：20px 上看着雅，缩到场上单位的 14px 时框吃掉半个字，压在浅色立绘上直接消失；
  2. **赭石亮底 + 墨字**：明度差只有 3~5:1，14px 的汉字糊成一团；朱砂/墨配纸白字是 8~10:1，同字号清清楚楚。**结论：深底色块 + 亮字，窄的只能是色相。**
- **尺寸**：卡面 18（两枚占 39/128）、场上单位 14、图鉴大卡 28（立绘区 290 宽，按 1.5 倍放大保持比例）。20 试过，两枚印占满卡宽三分之一，在手里比立绘还抢眼。
- **三处装配**：`CardView`（手牌/奖励/牌组预览）、`UnitView`（战场，阵亡时能把「这张是死战牌」和「援军加了 buff」连起来）、`codex` 大图（左侧列表有小印、右侧大图没有会很割裂）。
- **不翻译**：印面是中文单字，`Label` 不走 `I18n.T`。20px 方印里塞 "LS"/"GU" 必然糊；`i18n_test` 里「单个汉字＝朱砂印章式徽记」的白名单本来就是为这类保留字准备的。
- **测试**：新增 `keyword_stamp_test.gd` 76 项——判据（false/null 不算）、排列顺序、三档必须是深底且色相分开、字号随 `box` 走、三处装配不出界不压费用圆、**全卡池 70 张的印数与数据逐一比对**（任一方改字段名都会立刻红）、切语言不换字。
- **顺手修的旧 bug：英文卡名画出卡外**。`Label` 的最小尺寸默认等于整句文本宽度，「General · Warlord of the Dead」（29 字符）把 124 宽的卡名条顶成 230，名字直接压到邻牌上——**先 `set_size` 再开 `clip_text` 等于没开**（clip 时最小尺寸才是 0），顺序反了。同时把字号从「按字符数猜」改成 `Font.get_string_size()` 实测（中文一字≈1em、英文一字母≈0.5em，字符数根本不可比），最长那条现在 8 号正好放下。
- 全量 **1781 → 1862 项 + E2E 19** 全绿。

### 1.3 行军事件 10 → 16 个 ✅ 2026-11-03

- **先修了一个沉默的 bug（这也是本节真正的主菜）**：事件结算在 Godot 迁移时被简化成「一律发一张随机兵种牌，`fx.remove` 完全不处理」，于是三条旧事件在骗人——「奇书偶得·展卷夜读」写着三选一计谋牌，实际给兵种牌；「老卒请归」的两个删牌选项**什么也没发生**；「破釜沉舟」说两张只给一张。**所有既有测试都是绿的**，因为它们只断言「事件结算成功」，没人断言牌组真的变了。不修这个，新事件写什么 fx 都是空话。
- **做法**：把「选牌层」抽成 `ui/card_picker.gd`（多张选择、选满替换最早一张、无取消回调时只留确认按钮并居中、缩放随张数自适应），事件得牌/删牌与奖励页删牌三处共用；事件侧走 `Campaign.event_candidates()`（按 `fx.card` 过滤、抽 `张数×3` 张）与 `Campaign.add_card()` / `remove_card()`。
- **6 个新事件**（`js/campaign.js` 数据源 + `js/lang-en.js` 英文 + `export-data/export-i18n` 导出）：
  | 事件 | 三条路 | 新轴 |
  |---|---|---|
  | 借粮于民 | 立券（+3 军粮/−2 血）/ 强征（−1 血+兵种牌）/ 屯田（+2 摸牌/−1 血） | 军粮最大单次增益 |
  | 故人夜访（项伯） | 厚赠（敌 −2 军粮）/ 恳其缓颊（+4 血/−1 军粮）/ 闭门不见 | 「回血但要付军粮」的交换 |
  | 士卒思归 | 许诺还乡（+3 血/少摸一张）/ 严防哗变（两张牌/−3 血）/ 就地休整（+1 摸牌） | **draw 负值当代价**（首次） |
  | 渡河沉舟 | 减装急渡（+2 军粮/随机删一张）/ 等水退（+2 摸牌/敌 +1 军粮）/ 沿河缓行 | **enemyMana 正值**（自加难度换资源，首次） |
  | 假王之举 | 立封齐王（两张牌/−2 血）/ 遣使安抚（+1 摸牌）/ 斥其僭越（+3 血） | cardCount 2 |
  | 鸿沟之约 | 就此约和（+5 血/少摸一张）/ 追而击之（−4 血/三张牌）/ 虚与委蛇（+2 军粮） | **+5 血是全场最大**；cardCount 3 |
- **为什么值得加这 6 个**：事件是玩家最快见底的内容——8 关中间只在 10 个里抽，玩三四局就全撞过了，之后事件页从「抉择」退化成「点一下跳过」。新事件把三条轴线补成了「短期爆发 vs 长期续航」的真取舍，而不是又一堆扣血换牌。
- **测试**：`event_pick_test.gd` 新建 35 项（盯「选了之后牌组变没变、变的是不是那一张」）；campaign_test 133→152（fx 键白名单、glyph 单字、候选类型过滤、负 draw 与正 enemyMana 真进 rules）；i18n_test 187→211（新事件中英 + 选牌层扫描）；fonts_test 抓到 22 个新字缺字（重跑 `subset-fonts.py` + `--import`）。全量 **1862 → 1942 项 + E2E 19** 全绿。
